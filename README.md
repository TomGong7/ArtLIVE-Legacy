# ArtLIVE   画智体

## 中国画多模态文化交互与创新表达平台

---

## 一、项目概述

**ArtLIVE   画智体** 是一个以中国画为核心的文化交互平台。它的核心理念不是为中国画增加几个 AI 功能，而是让每一幅静态的中国画作品，转化为一个可以理解、对话、创作、评价、演绎和传播的文化世界。

依托权威中国画作品知识与专家创作经验，运用多模态智能技术，让静态中国画进入 **可读、可问、可创、可评、可演、可传播** 的多维文化空间。

**核心公式：** 一画为入口 · 知识为底座 · 智能为引擎 · 创演为路径 · 文博与美育为场景

## 四、界面外观设计

### 4.1 设计系统

平台采用 **CSS 变量** 驱动的统一设计系统，所有颜色、间距、圆角、阴影均通过变量集中管理，确保全局视觉一致性。

```
--bg:            #f5f0e7    宣纸底色
--bg-strong:     #ece3d5    旧纸深色
--surface:       rgba(...)  玻璃面板半透明
--text:          #2c2218    墨棕色正文
--text-soft:     #6b5f4e    浅墨色辅助文字
--accent:        #8b6b52    古铜色强调
--accent-strong: #5c3a26    深赭色重点
--line:          rgba(...)  暖棕线条
--shadow:        rgba(...)  暖棕阴影
```

### 4.2 古籍暖色调配色

整体配色灵感来源于 **宣纸、古墨、旧书卷**，以暖棕色系替代常见的冷色调，营造出翻阅古籍的沉浸感：

- **背景**：宣纸白（#f5f0e7）配合细微网格纹理，模拟纸张质感
- **文字**：墨棕（#2c2218）替代纯黑，柔和而不刺眼
- **强调**：古铜（#8b6b52）与深赭（#5c3a26），取自传统水墨颜料
- **面板**：半透明玻璃态，配合暖色高光，如透过毛玻璃看书页

### 4.3 玻璃态设计（Glassmorphism）

全局采用毛玻璃效果，面板背景为半透明暖色叠加模糊滤镜：

- 顶栏、卡片、面板均使用 `glass-panel` 样式
- 内阴影高光模拟玻璃边缘折射
- 悬浮时阴影加深，产生"浮起"的层次感
- 首页顶栏特别采用高透明度版本，让国画背景透过

### 4.4 字体排版

| 层级 | 字体栈 | 用途 |
|------|--------|------|
| 正文 | PingFang SC / Noto Sans SC / Microsoft YaHei | 界面功能文字、数字 |
| 标题 | Times New Roman + 宋体 / Songti SC | 页面标题、品牌英文 |

- 英文品牌名使用 Times New Roman，体现经典书卷气
- 中文标题使用宋体系列，呼应传统印刷美学
- 功能性数字使用中文字体栈，保持界面一致性

### 4.5 响应式布局

- 使用 `clamp()` 函数实现流畅的字体缩放
- 瀑布流列数从 4 列（桌面）到 1 列（手机）自适应
- 媒体查询覆盖 1024px、768px、480px 三个断点
- 顶栏导航在移动端优化间距和字号

### 4.6 动画与过渡

- 页面切换：淡入 + 缩放弹性动画
- 轮播切换：2 秒 opacity 淡入淡出
- 卡片悬浮：轻微上移 + 阴影加深
- 按钮交互：hover 时颜色渐变 + 轻微缩放
- 弹窗：居中缩放弹出，关闭时反向收起

### 4.7 背景装饰

- 大尺寸暖色渐变光球（`background-orb`），营造柔和氛围
- 细微网格纹理叠加在背景上，增加纸张质感
- 首页全屏国画轮播，配合渐变遮罩确保标题文字可读性

## 五、平台优势

### 5.1 零依赖纯原生

整个前端完全基于 **原生 HTML、CSS、JavaScript** 构建，不依赖任何第三方框架或库。这意味着：

- 极快的首屏加载速度，无框架运行时开销
- 零 npm 依赖，无需构建工具
- 代码可直接在任何静态服务器上部署
- 易于理解和维护，降低学习成本

### 5.2 数据持久化

利用浏览器 `localStorage` 实现完整的离线数据存储：

- 用户登录状态持久化
- 社区帖子、点赞、收藏数据本地存储
- 工坊生成作品历史保存
- 智能助手对话历史保存
- 画廊收藏列表持久化

### 5.3 模块化架构

每个功能模块独立为一个目录，包含 HTML、CSS、JS 三个文件：

- 模块间低耦合，可独立开发、测试、部署
- 全局样式和脚本通过 Main 目录共享
- 顶栏导航由 ArtStudio.js 统一生成，一处修改全局生效

### 5.4 完善的前端体验

- 登录/注册采用分步流程，降低用户认知负担
- 社区瀑布流支持动态列数调整
- 搜索过滤实时响应，无延迟
- 错误提示温和不打扰，3 秒自动消失
- 空状态引导明确，无数据时给出友好提示

### 5.5 文化主题深度整合

- 从中文字体、暖色调配色到古籍纹理，视觉元素全面服务文化主题
- 六维能力模型（读、问、创、评、演、传）形成完整的文化交互闭环
- 三层递进逻辑清晰展现从认知到实践的路径
- 设计理念（古韵今风、墨香纸韵、留白之美、笔触匠心）贯穿始终

## 六、后端接入指南

以下为后续接入后端的同学提供的指导。

### 6.1 需要后端化的模块

| 模块 | 当前实现 | 建议后端化 |
|------|---------|-----------|
| 登录/注册 | 本地 localStorage + 硬编码 Admin 账号 | 用户认证服务（JWT/Session） |
| 社区 | localStorage 存储帖子、点赞、评论 | 数据库 + REST API |
| 画廊 | 前端硬编码 8 幅作品数据 | 作品数据库 + 分页查询 |
| 知识库 | 前端硬编码知识条目 | 知识数据库 + 全文搜索 |
| 工坊 | 模拟生成结果 | 对接 AI 模型 API（文生图、图生图等） |
| 智能助手 | 模拟回复 | 对接大语言模型 API |
| 个人中心 | localStorage 读取 | 用户数据库查询 |

### 6.2 数据接口设计建议

#### 用户认证

```
POST   /api/auth/login          # 登录
POST   /api/auth/register       # 注册
POST   /api/auth/logout         # 登出
GET    /api/user/profile        # 获取用户信息
PUT    /api/user/profile        # 更新用户信息
```

#### 画廊

```
GET    /api/artworks            # 作品列表（支持 ?category=&search=&page=）
GET    /api/artworks/:id        # 作品详情
GET    /api/artworks/daily      # 每日推荐
POST   /api/artworks/:id/collect # 收藏/取消收藏
```

#### 社区

```
GET    /api/posts               # 帖子列表（支持 ?category=&search=&page=）
POST   /api/posts               # 发布帖子
GET    /api/posts/:id           # 帖子详情
POST   /api/posts/:id/like      # 点赞/取消点赞
POST   /api/posts/:id/collect   # 收藏/取消收藏
POST   /api/posts/:id/comments  # 发表评论
```

#### 知识库

```
GET    /api/knowledge           # 知识列表（支持 ?category=&search=&page=）
GET    /api/knowledge/:id       # 知识详情
GET    /api/knowledge/stats     # 知识分布统计
```

#### 工坊（AI 生成）

```
POST   /api/generate/painting   # 国画生成（文生图/图生图）
POST   /api/generate/music      # 音乐生成
POST   /api/generate/video      # 视频生成
POST   /api/generate/poetry     # 诗词生成
GET    /api/generate/history    # 生成历史
```

#### 智能助手

```
POST   /api/chat                # 发送消息（支持流式响应 SSE）
GET    /api/chat/history        # 会话历史
DELETE /api/chat/history        # 清空历史
```

### 6.3 前端数据层迁移要点

当前前端数据层集中在以下位置，后端化时需重点修改：

| 文件 | 需要修改的内容 |
|------|--------------|
| `Login/Login.js` | 登录验证改为 API 调用，token 存储 |
| `Community/Community.js` | 帖子 CRUD 改为 API 调用 |
| `Gallary/Gallary.js` | 作品数据从硬编码改为 API 获取 |
| `KnowledgeBase/KnowledgeBase.js` | 知识条目从硬编码改为 API 获取 |
| `Workshop/Workshop.js` | 生成请求改为 API 调用 |
| `Assistant/Assistant.js` | 对话改为 API 调用，支持 SSE 流式 |
| `Me/Me.js` | 收藏、作品、帖子从 API 获取 |
| `Main/ArtStudio.js` | 登录状态从 localStorage 改为 token 验证 |

### 6.4 建议的技术栈

- **后端框架**：Node.js (Express/Koa) 或 Python (FastAPI/Flask)
- **数据库**：PostgreSQL（关系数据） + Redis（缓存/会话）
- **AI 接口**：OpenAI API / 国内大模型 API（文生图、对话）
- **文件存储**：OSS（阿里云/腾讯云）存储用户上传图片和生成作品
- **部署**：Docker 容器化，Nginx 反向代理

### 6.5 安全性建议

- 所有 API 接口需做身份验证（JWT Token）
- 输入参数严格校验，防止 SQL 注入和 XSS 攻击
- 密码使用 bcrypt/argon2 哈希存储
- API 请求频率限制（Rate Limiting）
- 文件上传需校验类型和大小
- 生产环境启用 HTTPS
